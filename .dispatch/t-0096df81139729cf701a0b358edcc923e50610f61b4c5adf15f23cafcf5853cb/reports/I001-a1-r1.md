**Cause:** the only place loadout installs Homebrew is `scripts/release/install.sh`. When brew was missing, it ran Homebrew's installer as whoever ran the script, including a root shell or `curl … | sudo sh`. Homebrew's own installer only refuses root outside containers, so it doesn't fully protect against this. The Rust CLI never installs Homebrew.

**Fix:** when brew is missing and the effective UID is 0, `install.sh` now stops before downloading anything. It tells you to run it again as your own user (under sudo it names `$SUDO_USER`) or to pass `--no-homebrew`. If `id -u` fails, it also stops rather than guessing.
- Running as root still installs loadout if brew is already there or you pass `--no-homebrew`.
- Non-root installs behave as before.

**Checks:**
- `scripts/ci/check.sh` at head: rustfmt, clippy, the Rust tests and the release-script tests all passed.
- The new tests fail on the old script (all 4 root/sudo cases) and pass on the fix.
- I ran three real-identity runs with a stub Homebrew installer that just prints its user ID. Nothing touched the host's Homebrew:
  - **Root (user namespace):** refused, and the stub never ran.
  - **Real `sudo`:** refused with the sudo-specific message.
  - **UID 1000:** the stub ran as UID 1000, so normal installs are unaffected.

**Gaps:**
- On a host that already has Homebrew, the existing "Homebrew missing" tests (and the new root/sudo refusal test) skip themselves, and this machine has it. I ran them separately in a namespace that hides it, as described above.
- The "before" sudo run was simulated (root plus `SUDO_USER` set); the "after" sudo run used real `sudo`.
- Nothing was run on a Mac; the macOS path was only covered by faking the OS name in tests.

**Decisions:**
- **Stop, don't switch users:** the installer doesn't re-run Homebrew's installer as `$SUDO_USER`, because loadout itself would still land in root's home.
- **Stop, don't skip quietly:** as root without brew it exits with guidance instead of carrying on without Homebrew.
- **Tests fake the user ID** and default to non-root, so the tests behave the same when CI or a container runs them as root.

**Gates:** none. **Follow-ups:** none required. A Mac run would cover the macOS gap above.
