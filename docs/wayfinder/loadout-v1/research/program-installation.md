# Research: Program installation per OS

Ticket: [Program installation per OS](../tickets/02-program-installation.md)
Gathered: 2026-10-23. Facts only; no recommendation on how a loadout declares **programs** (that belongs to the Program model ticket).

Method notes: primary docs, man pages, and source were read. Where a page was silent, the table says "not documented" rather than guessing. Package-index facts (winget manifests, Homebrew cask JSON, Scoop buckets, Flathub, Repology, crates.io) were read from each project's public API/repo on 2026-10-23, so versions are a snapshot. Only `brew --version`/`--help` style local checks were run (Homebrew 7.0.10 on this macOS machine); nothing was installed.

### Per-manager notes

- **Homebrew prefix**: `/opt/homebrew` (Apple Silicon), `/home/linuxbrew/.linuxbrew` (Linux). "Homebrew can be installed for a non-admin account" via a writable prefix or `--path`; custom prefixes are "Tier 1 requirements and a stability caveat" ([Installation](https://docs.brew.sh/Installation)). Installer is bash-only; `NONINTERACTIVE=1` skips prompts.
- **Brew dry run**: `brew install -n/--dry-run` exists (`brew install --help`, 7.0.10).
- **winget exit codes** relevant to scripting ([returnCodes.md](https://github.com/microsoft/winget-cli/blob/master/doc/windows/package-manager/winget/returnCodes.md)): `0x8A150061` already installed, `0x8A15010D` another version present, `0x8A15010E` higher version present, `0x8A15002B` no applicable update, `0x8A150014` no packages found, `0x8A150019` command requires admin, `0x8A150010` no applicable installer, `0x8A150109/10A/10B` reboot variants, `0x8A15010C` cancelled by user. The page lists no code specific to a declined UAC prompt.
- **winget limits**: not supported in the SYSTEM context; the `Microsoft.WinGet.Client` PowerShell module is the documented alternative ([Troubleshooting](https://learn.microsoft.com/en-us/windows/package-manager/winget/troubleshooting)). Local manifest installs must be enabled by an admin. Non-interactive flags: `--silent`, `--accept-package-agreements`, `--accept-source-agreements`, `--disable-interactivity` ([install](https://learn.microsoft.com/en-us/windows/package-manager/winget/install)). `winget uninstall` also removes apps not installed by winget ([uninstall](https://learn.microsoft.com/en-us/windows/package-manager/winget/uninstall)); `--source winget` avoids Store agreement prompts.
- **Scoop global**: `C:\ProgramData\scoop`; after a first global install the local-system account needs a reboot to see env changes ([Global Installs](https://github.com/ScoopInstaller/Scoop/wiki/Global-Installs)).
- **Chocolatey** `--install-directory` is "licensed editions only" ([install](https://docs.chocolatey.org/en-us/choco/commands/install/)).
- **Flatpak** per-user also needs a user remote (`flatpak --user remote-add …` appears in the man page examples).
- **Snap**: `snap list --all` shows disabled older revisions (so a plain `grep` can over-match) (forum guide).

Facts about the snapshot:
- Among 7,804 casks in the Homebrew API, 659 declare a `pkg` artifact. None of the browser casks above do ([cask.json](https://formulae.brew.sh/api/cask.json)).
- Chrome and Firefox on Windows are declared `Scope: machine` in their winget manifests (no `user` scope variant listed in the installer files read). Chrome additionally declares `elevatesSelf`.
- Arc's winget package ships as MSIX; MSIX is described as having "reliable WinGet behavior" for scope ([Troubleshooting](https://learn.microsoft.com/en-us/windows/package-manager/winget/troubleshooting)).
- Linux: Chrome, Firefox, Zen, Chromium are on Flathub; Firefox and Chromium have snaps. Debian/Ubuntu/Fedora/openSUSE/Arch package names for Firefox differ (see §4).
- Cask artifact `app` places the bundle in `/Applications` ([Cask Cookbook](https://docs.brew.sh/Cask-Cookbook)); the cookbook page read does not mention `~/Applications` (an `appdir` variable is referenced).

### Elevation summary for browsers (per sources above)
- macOS cask `app` artifacts: no `pkg`, so no installer-run step is declared for these four. Whether writing to `/Applications` needs an admin password for a given account: not stated in the sources read.
- Windows: winget Chrome/Firefox/Zen manifests are machine scope; Scoop installs per-user (`~\scoop`) by default.
- Linux: Flatpak supports `--user`; apt/dnf/zypper/pacman/snap system installs are privileged operations per §1.

## 6. Open or conflicting facts

1. **Homebrew already-installed exit code**: the Manpage and `install.rb` describe upgrading outdated formulae but not the exit code when current. Not verified (no installs were run).
2. **Cask sudo**: Cask Cookbook says `pkg` payloads run via `/usr/sbin/installer` but never states they require sudo; the Installation page says some casks "still need elevated privileges" and `HOMEBREW_NO_SUDO=1` rejects them.
3. **`/Applications` write for casks without a `pkg`**: not stated in the sources read for non-admin macOS accounts. The Cookbook mentions `appdir` but not `~/Applications`.
4. **Homebrew docs vs local**: Installation page says non-admin accounts are supported but also labels custom prefixes with stability caveats; the two statements coexist.
5. **winget scope**: `--scope` option exists, yet the docs say EXE behavior "is not necessarily deterministic" and user-scope installs "may still require UAC". Chrome and Firefox manifests declare machine scope only (installer files read), so `--scope user` has no declared target for them.
6. **winget list not-found code**: `0x8A150014` is listed as "No packages found"; the page doesn't tie it to `list` specifically.
7. **Chocolatey `list`**: the doc page read doesn't document `--local-only` (earlier 1.x flag); in 2.x list is local by default per other docs, which this pass didn't fetch. The `name|version` limit-output layout isn't spelled out on the page read. Already-installed behavior is undocumented on the `install` page.
8. **Scoop**: wiki Commands page lists no options/JSON for `list`; `scoop export` is the documented JSON source. Whether the `scoop` binary in current `master` differs from the wiki: not checked.
9. **apt, dnf, pacman root requirement**: no explicit sentence found on the pages read; apt-get.8 only mentions simulations by non-root. Not stating root-needed here is a gap, not evidence of the opposite.
10. **pacman `-Q` exit status** for a missing package: not on the man page read.
11. **snap**: already-installed exit status undocumented in sources found; the REST access-level docs don't say which endpoints use polkit ("if available").
12. **Flatpak**: `flatpak list`/`info` exit status when absent: not read. `flatpak info` "machine-readable" output is described but without a schema.
13. **npm/bun**: idempotence and exit codes not documented in pages read; npm global prefix defaults to Node's own location, so user-vs-system scope depends on how Node was installed.
14. **uv tool list**: no `--json` flag in `ToolListArgs` (source read) while pipx has JSON; uv's docs page for tools doesn't document uninstall details beyond environment persistence.
15. **cargo-binstall**: the README doesn't describe the already-up-to-date path, `--dry-run`, or JSON output; maintenance is active (crate 1.26.0, 2026-10-17).
16. **Repology**: a project's `binname`/`srcname` for a given repo can be a variant (`firefox-i18n-es-es` on Arch, `firefox-eme-free` in Scoop) rather than the main package; first-returned entry isn't reliably the primary one. Repology had no winget/flathub/snapcraft entries for `firefox` in the queried data.
17. **Home-manager on Windows**: not stated in pages read. Nix itself on Windows: not researched.
18. **mise**: `mise ls --json` and the full list of backends (asdf, npm, pipx, ubi, vfox) are referenced elsewhere but not confirmed on pages read.
19. **WinGet Configuration vs DSC v3**: the configuration docs describe PowerShell DSC resources (Windows); DSC v3's own overview describes a cross-platform `dsc` CLI. The relationship (WinGet as "early partner") is stated, but whether `winget configure` itself consumes DSC v3 documents wasn't established here.
20. **Arc Windows**: winget lists MSIX Arc 1.99.0.265 while Homebrew lists Arc 1.170.0 for macOS; unrelated Scoop `arc` is an archiver, so the same token means different software across managers.
